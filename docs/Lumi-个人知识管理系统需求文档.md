## 1. 项目概述

本项目(Lumi)是一个自用的个人知识管理系统，用于统一收集、整理和管理用户日常浏览的网络内容。

用户平时会浏览大量图文、视频、音频等内容，例如微信公众号文章、博客文章、技术文章、资讯网站、视频平台内容等。本系统希望将这些分散在不同平台的内容统一保存到自己的知识库中，方便后续阅读、搜索、总结和问答。

当前阶段主要实现**图文内容**的采集、转换、保存和阅读；视频、音频等内容暂不实现，但系统设计需要预留扩展能力，方便后续接入。

---

## 2. 项目目标

本项目的目标是实现一个可自用、可扩展的知识管理平台，核心目标包括：

1. 支持从不同网站采集图文内容。
2. 支持将采集到的图文内容转换为 Markdown 格式。
3. 支持将内容保存到个人知识库中。
4. 支持在 Web 端查看和管理已保存内容。
5. 支持通过浏览器插件保存当前正在浏览的页面。
6. 支持后续接入 AI 总结、搜索问答等能力。
7. 支持后续扩展视频、音频等内容类型。
8. 支持后续扩展 CLI 端。

---

## 3. 当前实现范围

当前阶段需要实现以下三部分：

### 3.1 Web 端

Web 端用于用户管理和阅读已保存的内容。

主要需求：

1. 查看已保存的文章列表。
2. 查看文章详情。
3. 支持 Markdown 内容展示。
4. 支持通过粘贴 URL 导入普通网页内容。
5. 支持查看内容导入状态。
6. 支持基础搜索功能。

---

### 3.2 浏览器插件

浏览器插件用于在用户浏览网页时，将当前页面保存到系统中。

主要需求：

1. 支持保存当前浏览器页面。
2. 支持保存用户选中的页面内容。
3. 支持读取当前页面的标题、URL 和页面内容。
4. 支持将页面内容提交给后端系统。
5. 支持配置后端服务地址和访问凭证。
6. 支持微信公众号等后端无法直接访问的页面导入。

说明：

微信公众号等页面可能存在访问限制或反爬机制，后端无法直接通过 URL 获取内容，因此需要浏览器插件在用户已打开页面的情况下读取页面内容并提交给后端。

---

### 3.3 后端服务

后端服务负责接收、处理、存储内容，并为 Web 端和浏览器插件提供接口。

主要需求：

1. 接收 Web 端提交的 URL。
2. 接收浏览器插件提交的页面内容。
3. 提取网页正文内容。
4. 清洗外部 HTML 内容。
5. 将图文内容转换为 Markdown。
6. 保存文章内容和基础元数据。
7. 提供文章查询接口。
8. 提供导入任务状态查询能力。
9. 为后续 AI、搜索问答、视频音频处理等能力预留扩展。

---

## 4. 内容类型范围

### 4.1 当前支持的内容类型

当前阶段只实现**图文内容**，包括但不限于：

1. 普通网页文章。
2. 博客文章。
3. 技术文章。
4. 微信公众号文章。
5. 图文资讯页面。
6. 用户选中的网页片段。

当前图文内容的基本处理目标是：

```txt
网页内容 / 页面快照
  -> 提取正文
  -> 转换为 Markdown
  -> 保存到系统
  -> Web 端阅读
```

---

### 4.2 后续扩展的内容类型

以下内容类型当前不实现，但需要在系统设计中预留扩展空间：

1. 视频内容。
2. 音频内容。
3. PDF 内容。
4. RSS 内容。
5. 其他平台内容。

后续视频、音频内容可能需要支持：

1. 获取标题、作者、封面等元数据。
2. 获取字幕或转录文本。
3. 将转录文本整理为 Markdown。
4. 支持总结、搜索和问答。

---

## 5. 导入方式需求

系统需要支持多种内容导入方式。

### 5.1 URL 导入

用户在 Web 端粘贴文章 URL，系统自动抓取网页内容并保存。

适用场景：

1. 普通博客。
2. 技术文章。
3. 普通资讯网站。
4. 不需要登录或特殊访问权限的网页。

---

### 5.2 浏览器插件导入

用户打开目标网页后，通过浏览器插件保存当前页面内容。

适用场景：

1. 微信公众号文章。
2. 需要登录后才能查看的网页。
3. 动态渲染页面。
4. 后端无法直接抓取的页面。

---

### 5.3 选中内容导入

用户可以在网页中选中一部分内容，通过浏览器插件只保存选中的内容。

适用场景：

1. 只想保存文章中的某一段。
2. 保存网页中的局部内容。
3. 保存摘录内容。

---

### 5.4 后续 CLI 导入

CLI 端当前不实现，但后续需要支持通过命令行导入内容。

可能的使用方式包括：

```bash
kb add https://example.com/article
kb add ./article.md
```

因此当前系统需要为 CLI 端预留接口和扩展能力。

---

## 6. AI 能力需求

AI 能力可以分阶段实现。

当前阶段可以先预留，不要求完整实现。

后续需要支持：

1. 单篇文章总结。
2. 文章要点提取。
3. 自动标签生成。
4. 基于已保存内容的搜索问答。
5. 基于单篇文章的问答。
6. 基于知识库的语义检索。

AI 能力应作为系统的扩展能力，不应影响当前图文采集和阅读主流程。

---

## 7. 搜索需求

当前阶段需要支持基础搜索。

基础搜索包括：

1. 按标题搜索。
2. 按正文内容搜索。

后续可以扩展为：

1. 全文搜索。
2. 语义搜索。
3. 混合搜索。
4. AI 问答式搜索。

---

## 8. 阅读和管理需求

Web 端需要提供基础的内容管理能力。

当前阶段需要支持：

1. 查看文章列表。
2. 查看文章详情。
3. 阅读 Markdown 内容。
4. 查看原文链接。
5. 查看文章标题、来源、作者等基础信息。
6. 查看导入状态。
7. 删除文章。

后续可以扩展：

1. 标签管理。
2. 收藏夹。
3. 阅读状态。
4. 归档。
5. 批注。
6. 高亮。
7. 导出 Markdown。

---

## 9. 安全需求

由于系统会处理外部网页内容，需要注意安全问题。

主要需求：

1. 外部 HTML 内容需要清洗。
2. Markdown 渲染时需要防止 XSS 攻击。
3. 后端接口需要访问控制。
4. 浏览器插件访问后端时需要凭证。
5. 不应设计绕过平台访问限制的批量抓取能力。
6. 仅保存用户主动导入且有权限访问的内容。

---

## 10. 扩展性需求

系统需要为后续能力预留扩展空间。

需要预留的方向包括：

1. 视频内容导入和转录。
2. 音频内容导入和转录。
3. CLI 端。
4. AI 总结和问答。
5. 向量检索。
6. 图片本地化存储。
7. PDF 导入。
8. RSS 导入。
9. 更多站点适配规则。
10. 多种对象存储服务。
11. 多种大模型服务。

---

## 11. 当前不实现的内容

当前阶段明确不实现：

1. 视频内容解析。
2. 音频内容解析。
3. CLI 端。
4. PDF 解析。
5. RSS 自动订阅。
6. 复杂知识图谱。
7. 复杂多用户权限系统。
8. 完整 AI Agent 能力。

但这些能力后续可能会加入，因此系统需求和架构不应完全写死为只支持图文、只支持 Web 和插件。

## 13. 一句话总结
